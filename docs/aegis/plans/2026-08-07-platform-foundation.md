# 一体化运维平台实施计划

## 状态

- 对应规格：[一体化运维平台设计规格](../specs/2026-08-07-platform-design.md)
- 覆盖范围：阶段一全部任务，阶段二至四给出里程碑与依赖，细化留待各阶段启动前。
- 前置条件：规格文档经用户复核确认。

## 计划原则

阶段一的目标不是「搭好地基再说」，而是**用两个真实场景压测核心抽象**：批量命令执行与资产台账。这两个场景分别检验任务框架与资产模型，若抽象有误，此时返工代价最小。

每个工作项标注验证方式。没有验证方式的工作项不允许标记完成。

## 阶段一：地基与资产

### A. 工程基础设施

| 编号 | 任务 | 验证方式 |
| --- | --- | --- |
| A1 | 仓库结构与模块边界（`gateway` / `api` / `scheduler` / `worker` / `agent` / `frontend`） | 各模块可独立启动，无循环依赖 |
| A2 | PostgreSQL 16 + Redis 7 本地编排（docker compose） | 一条命令拉起完整依赖 |
| A3 | Alembic 接入与首个迁移 | 空库与存量库均可迁移，可回滚一版 |
| A4 | 配置体系（pydantic-settings，环境变量优先） | 无默认值的必需项缺失时启动即失败 |
| A5 | 结构化日志（JSON，含 trace_id） | 一次请求的全链路日志可按 trace_id 串联 |
| A6 | CI：lint、typecheck、单测、迁移检查 | PR 触发全流程，任一失败阻断合并 |

### B. 资产域

| 编号 | 任务 | 验证方式 |
| --- | --- | --- |
| B1 | `assets` 表与资产类型定义（host / service / cluster / database） | 迁移生效；四种类型均可创建 |
| B2 | 资产标签与标签选择器 | 选择器可按标签组合筛选，含否定条件 |
| B3 | 资产关系表 `asset_relations`（承载 / 依赖 / 归属） | 关系可双向查询，环路被拒绝 |
| B4 | 资产来源标记与外部对账占位（source / external_id） | 手工与自动来源可区分，重复 external_id 被拒 |
| B5 | 资产 CRUD API 与列表筛选 | 越权访问被拒；筛选结果与选择器语义一致 |
| B6 | 资产管理前端（列表、详情、编辑、关系视图） | 四种类型均可完成增删改查 |

### C. 身份与权限域

| 编号 | 任务 | 验证方式 |
| --- | --- | --- |
| C1 | 用户、角色、权限码模型 | 权限码枚举完整，角色可组合 |
| C2 | 资源范围授权（按标签选择器授权，非逐个资产） | 新增匹配标签的资产自动纳入既有授权 |
| C3 | 鉴权中间件与权限装饰器 | 每个端点均声明所需权限码，未声明则启动失败 |
| C4 | 会话与令牌（含令牌版本失效） | 改密后旧令牌立即失效 |
| C5 | 用户与角色管理前端 | 可完成授权与回收，变更入审计 |

### D. 任务域（核心抽象验证）

| 编号 | 任务 | 验证方式 |
| --- | --- | --- |
| D1 | `task_definitions` / `tasks` / `task_logs` 模型与状态机 | 非法状态跃迁被拒绝 |
| D2 | 基于 `SELECT ... FOR UPDATE SKIP LOCKED` 的抢占式领取 | 多副本并发领取无重复，见 [任务调度 ADR](../adr/2026-08-07-task-scheduling.md) |
| D3 | 租约与心跳续期、超时回收 | worker 强杀后任务被回收重派，不重复副作用 |
| D4 | 幂等键与恰好一次语义 | 同一幂等键重复提交只执行一次 |
| D5 | 任务日志流式写入与查询 | 长任务日志可实时追加、按 run 检索 |
| D6 | 定时任务（数据库驱动，非进程内注册） | 多调度副本下同一定时任务只触发一次 |
| D7 | 三类差异化任务接入验证：即时命令、批量作业、周期探活 | 三类均走同一框架，无旁路执行路径 |

### E. Agent

| 编号 | 任务 | 验证方式 |
| --- | --- | --- |
| E1 | protobuf 契约定义与代码生成 | 前后端契约由同一份 proto 生成 |
| E2 | 注册与审批流（pending / approved / rejected / revoked） | 未审批 Agent 无法获取任何配置 |
| E3 | 实例 CA 与 mTLS 证书签发、轮换、吊销 | 吊销后连接被拒；轮换不中断在线会话 |
| E4 | 控制通道（双向流：心跳、配置下发、任务派发） | 网络中断后自动重连，不丢任务 |
| E5 | 连接归属注册（Redis）与跨副本任务路由 | Agent 连在副本 A，从副本 B 发起的任务可送达 |
| E6 | 命令执行与结果回传（含子进程环境隔离） | 子进程不继承打包器注入的库搜索路径 |
| E7 | 离线自治与结果暂存补报 | 断网期间结果本地暂存，恢复后按序补报且不重复 |
| E8 | PyInstaller 打包与多发行版兼容矩阵 | 目标镜像 self-test 通过，覆盖反向 SONAME 组合 |

### F. 审计域

| 编号 | 任务 | 验证方式 |
| --- | --- | --- |
| F1 | 统一审计模型（主体、动作、对象、结果、请求上下文） | 字段足以还原「谁在何时对什么做了什么，结果如何」 |
| F2 | 写路径强制审计（框架层拦截，非各处手写） | 新增写端点若未产生审计记录，测试失败 |
| F3 | 配置变更前后值留存 | 任意配置变更可查看 diff |
| F4 | 审计查询与导出前端 | 可按主体、对象、时间、动作组合检索 |

### G. 可用形态收口

| 编号 | 任务 | 验证方式 |
| --- | --- | --- |
| G1 | 批量作业前端（目标选择、执行、实时日志、结果汇总） | 对 50 台目标发起批量命令，实时看到逐台结果 |
| G2 | 平台自身可观测性（指标、健康检查、就绪探针） | 关键队列深度与任务时延可观测 |
| G3 | 集群部署验证 | 杀掉任一副本，进行中操作不丢失 |
| G4 | 阶段一压测 | 达成规格容量目标中与任务、Agent 相关的指标 |

### 阶段一依赖顺序

```
A（基础设施）
├─→ B（资产）─┐
├─→ C（权限）─┼─→ D（任务）─→ E（Agent）─→ G（收口）
└─→ F（审计）─┘
```

F 必须与 B、C 并行完成而非事后补充：审计是框架层能力，事后补等于重写所有写路径。

## 后续阶段里程碑

**阶段二：监控与告警**。依赖 D（任务框架承载周期探活）与 E（Agent 执行探活）。关键风险是健康规则引擎的表达能力，需在阶段二启动前确定规则语法边界。

**阶段三：交付与访问**。交付流水线依赖 D 的长任务与日志流；会话代理依赖 E 的实时通道。会话代理启动前须按 [自研会话代理 ADR](../adr/2026-08-07-bastion-self-build.md) 重新评估自研决策。

**阶段四：拓扑与分析**。依赖阶段三产出的部署关系数据，见 [拓扑数据来源 ADR](../adr/2026-08-07-topology-data-source.md)。

## 不做的事

- 不为「以后可能需要」预留抽象层。多租户、插件市场、跨云编排在明确需求出现前不设计。
- 不在阶段一引入 Kubernetes Operator、服务网格、eBPF 采集。
- 不接受任何绕过任务框架的执行路径，包括「临时脚本」与「调试接口」。
