# 主动注册 Agent 实施计划

## Goal

按已确认的 Agent 设计规格交付双执行模式：远程 Agent 主动注册、管理员审批、独立密钥认证、gRPC TLS 配置拉取、本地探活与自动拉起、离线自治、结果补报、异步手动命令，以及 x86_64/ARM64 的 glibc 2.17/2.28 四套二进制发布产物。

## Architecture

- `Host/Service/ServiceProbe/health_rule_json` 保持唯一业务配置源。
- `execution_mode=ssh` 继续使用现有中心调度和 Paramiko；`execution_mode=agent` 仅接受 Agent 心跳和结果，不存在运行时回退。
- FastAPI 只新增 Agent 管理与命令状态 API；独立 gRPC 服务承载 Agent 注册、认证、同步和报告，不把协议逻辑堆入现有 `monitoring.py`。
- Agent 是独立 Python 包，使用 PyInstaller 构建单文件二进制；本地 SQLite 保存身份、配置、outbox、结果序号和命令幂等记录。
- 中心状态变更和飞书发送仍由中心统一处理，Agent 不持有告警配置。

## Tech Stack

- 中心：Python 3.9+、FastAPI、SQLAlchemy、SQLite、APScheduler、Paramiko、HTTPX。
- Agent：Python 3.9+、gRPC TLS、protobuf、SQLite、cryptography、tomli、PyInstaller、systemd。
- 前端：React 19、TypeScript、Vite、Lucide。
- 发布：GitHub Actions、manylinux2014、manylinux_2_28、原生 ARM64 Runner 或 QEMU。

## Requirement Ready Check

- 需求来源：已确认书面规格和当前会话追加约束。
- 场景：新 Agent 申请、管理员审批新建/绑定、在线同步、中心断线、手动命令、撤销与轮换、SSH/Agent 启动用户。
- 验收来源：Agent 设计规格“验收标准”和发布兼容矩阵。
- 开放阻塞问题：无。
- Decision: ready。

## Compatibility Boundary

- 旧 SQLite 数据升级时保持 `execution_mode=ssh`，升级本身不清除 SSH 信息。
- 只有管理员确认绑定并切换具体主机时，才永久清除 `password_encrypted`、`private_key_path`、SSH 端口和原 SSH 用户信息。
- 服务、探活历史、资源组授权、告警关系和主机身份不得删除或重新编号。
- SSH 模式 API 与定时行为保持可用；Agent 模式不得进入 SSH 调度器。
- `start_user` 为空时不调用 `sudo` 或 `runuser`，保持当前用户执行。
- 目标节点安装不依赖 Docker。

## Change Necessity

- 用户可见需要：没有中心入站 SSH 条件时，节点仍可主动接入并自治监测。
- 非代码方案：继续使用 SSH 无法满足主动注册、离线自治和二进制 Agent。
- 最小边界：新增 Agent 执行器和协议；复用现有服务配置、规则、权限和告警。
- Decision: code-change。

## Existence Check

- 新表与 Agent 路由：现有用户 JWT、SSH 调度和服务路由不能表达节点独立身份、审批与异步命令，新增有必要。
- Agent 本地 SQLite：中心断线自治和幂等补报需要持久 outbox，内存状态不足。
- 独立结果处理器：复用中心告警发送，但不扩张 SSH `MonitoringService` 为双协议控制器。
- 新前端页面：审批、撤销和运行状态不属于主机编辑表单。
- Decision: add-with-proof。

## Architecture Integrity Lens

- 不变量：服务配置只有中心一份，主机同时只有一个执行器。
- 规范所有者：中心模型/协议负责配置和状态；Agent engine 负责本地执行；告警 dispatcher 负责发送。
- 重叠检查：SSH 与 Agent 共享探活结果契约，不共享调度入口。
- 退休边界：切换 Agent 后 SSH 凭据和该主机 SSH 执行路径立即失效，不保留自动回退。
- Verdict: aligned。

## Plan-Time Complexity Check

- 当前压力：`backend/app/monitoring.py` 约 350 行，`backend/tests/test_api.py` 已超过 500 行。
- 新边界：新增 `agent_*` 模块和拆分测试文件，避免继续扩大上述文件。
- SQLite 主机表重建为最高风险步骤，单独实现、备份式测试和外键完整性检查。
- Budget result: within-budget，前提是协议、结果处理、Agent 执行和发布保持独立文件。

## Risks

- SQLite hosts 表重建可能破坏外键：使用真实旧库 fixture、事务、索引对比和 `foreign_key_check`，失败不写迁移标记。
- 首次 claim 响应丢失可能锁死 Agent：临时加密副本保留到首次认证心跳成功。
- 断线补报可能告警风暴：按 sequence 幂等入库，每服务只基于最终差异告警一次。
- 命令可能重复执行：领取前后均以 `command_id` 在中心和 Agent 本地持久去重。
- Agent root 权限放大启动命令风险：仅管理员配置，命令类型固定，启动用户使用 argv，文档明确权限。
- PyInstaller ABI 风险：分别构建 glibc 2.17/2.28，四产物在明确发行版矩阵验证，不假设单一包万能兼容。

## Retirement

- 切换 Agent 的主机永久退休 SSH 凭据和 SSH 执行路径，不保留自动回退。
- 现有 SSH 实现继续服务未切换主机，不属于待删除旧逻辑。
- Agent 协议不在 `MonitoringService` 中保留第二份配置或规则所有者。
- 旧同步服务动作响应只在 SSH 模式保留；Agent 模式使用明确的 queued command 契约。
