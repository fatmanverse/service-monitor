# ADR: Agent 执行模式、身份与离线自治

## 状态

已接受。

## 背景

服务监控需要支持中心通过 SSH 执行探活，也需要支持远程节点主动连接中心。两条执行路径如果同时拥有同一服务，会造成重复探活、状态覆盖和自动拉起冲突；共享 Agent 密钥会扩大单节点泄露影响；中心断线时完全停止本地探活又无法满足节点自治要求。

## 决策

- `Host.execution_mode` 是执行路径的唯一来源，只允许 `ssh` 或 `agent`。
- 主机显式切换为 Agent 时，在同一数据库事务中永久清除 SSH 端口、密码和私钥信息，不自动回退 SSH。
- `Host`、`Service`、`ServiceProbe` 与健康规则仍是唯一配置源，不建立 Agent 专属服务配置表。
- Agent 使用独立 UUID、claim token 和长期高熵密钥。中心只保存带 `APP_SECRET` 的 HMAC；临时可领取密钥使用应用密钥加密。
- Agent 控制面只使用 TLS gRPC，管理员审批和查询继续使用 FastAPI JWT API。protobuf 是网络契约的唯一来源。
- Agent 使用本地 SQLite 持久化身份、完整配置、报告 outbox、单调序号和命令幂等结果。中心断线时继续按最后一份完整配置执行。
- 报告以 `agent_id + report_id` 和单调 `report_sequence` 去重；历史补报写日志，但只基于最终状态差异发送一次延迟告警。
- 手动 Agent 操作进入中心命令队列，前端轮询终态；SSH 操作保持同步。

## 后果

- 切换为 Agent 是不可逆的 SSH 凭据删除操作；切回 SSH 必须重新配置凭据。
- Agent 无法连接中心时仍能探活和拉起，但无法发送中心侧飞书告警。
- Agent 被撤销或密钥轮换后旧密钥立即失效。
- 发布必须分别验证 x86_64/ARM64 与 glibc 2.17/2.28 产物，不能假设单一 Linux 二进制兼容全部节点。
