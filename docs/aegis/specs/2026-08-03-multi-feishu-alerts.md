# 多飞书告警设计规格

## 目标

- 告警管理可维护多个飞书机器人配置。
- 一个服务可关联多个告警配置，离线与恢复时发送到全部已启用配置。
- 一个节点可关联多个告警配置，首次离线、在线转离线和离线恢复时发送到全部已启用配置。
- 未关联配置时不告警；删除配置只解除关联，不删除服务。

## 数据契约

- `alert_configs` 增加唯一名称，Webhook 继续加密存储。
- `service_alert_configs` 作为服务与告警配置的唯一运行时关联来源。
- `host_alert_configs` 作为节点与告警配置的唯一运行时关联来源。
- 旧 `services.alert_enabled` 保留为迁移备份，不参与运行时判断。
- 旧单例告警迁移为“默认飞书机器人”，旧启用告警的服务自动关联它。

## API 契约

- `GET /api/alerts`
- `POST /api/alerts`
- `PUT /api/alerts/{id}`
- `DELETE /api/alerts/{id}`
- `POST /api/alerts/{id}/test`
- 服务创建与更新使用 `alert_config_ids`，服务输出提供告警配置引用列表。
- 节点创建与更新使用 `alert_config_ids`，节点输出提供告警配置引用列表。

旧的 `/api/alerts/config` 单例接口不再提供；旧 `alert_configs.id = 1` 数据只通过迁移进入新列表模型。

## 验收

- 可新增、编辑、删除、测试多个飞书机器人。
- 服务可多选机器人，状态变化发送到所有启用且已配置的目标。
- 节点可多选机器人；节点首次探活成功不告警，首次失败和后续离线/恢复状态变化发送告警。
- 节点离线期间不执行其服务探活、自动拉起或服务告警，且不覆盖服务最后一次状态。
- 旧数据库迁移幂等且不丢失原 Webhook、服务和告警启用关系。
