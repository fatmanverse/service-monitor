# 服务监控设计规格

## 目标

交付一个可在单机直接运行的服务监控系统，支持约 200 台主机、1000 个服务，定时任务最小间隔 60 秒。

## 架构

- React + TypeScript 管理端调用 FastAPI JSON API。
- FastAPI 使用 SQLAlchemy 管理 SQLite；SQLite 外键负责主机到服务、授权和记录的级联删除。
- APScheduler 定期扫描到期任务，所有手动和定时探活都调用同一监测服务。
- Paramiko 负责 SSH 主机探活、进程检查和启动命令执行。
- HTTPX 负责 GET/POST 探活和飞书 Webhook。

## 权限不变量

- 管理员可管理主机、服务、告警配置、用户和授权。
- 一个服务只属于一个资源组，一个用户可授权多个资源组。
- 普通用户只可读取已授权资源组中的服务及其所属主机摘要。
- 普通用户可以手动探活已授权服务，但不能执行启动命令或修改配置。
- 用户名、主机名、资源组名和服务名按各自作用域唯一。

## 监测行为

- 主机探活通过建立 SSH 连接确认可达性。
- 每个服务包含一个或多个进程、GET、POST 探活项。
- 进程探活通过 SSH 执行 `pgrep -f`；匹配内容为 `systemctl status <unit>` 或 `systemctl is-active <unit>` 时改用 systemd 活跃状态检查，unit 只允许安全字符。
- HTTP 探活支持 GET/POST、Headers JSON、JSON Body、Basic 和 Bearer 认证。
- 在线规则保存为递归 JSON 表达式树，支持任意嵌套 `AND` / `OR`；叶子引用探活项稳定键。
- 每个启用探活项必须在规则中且只能出现一次；规则结果为真时服务在线。
- 服务由在线变为离线时向其关联的全部启用飞书机器人告警；由离线恢复在线时发送恢复通知。
- 开启自动拉起时，离线后执行启动命令并立即复检；可选启动用户由 Agent 扩展规格定义，启动失败或复检仍离线时保留离线结果。

## 安全边界

- 密码使用 PBKDF2 哈希保存。
- SSH 密码和 HTTP 认证密钥使用由 `APP_SECRET` 派生的 Fernet 密钥加密保存。
- 登录令牌使用 HS256 签名。
- 服务启动命令仅管理员可配置或手动执行。

## 验收

- 主机、服务、用户和告警配置 API 可用。
- 60 秒以下周期被拒绝。
- 删除主机后对应服务和授权不可再查询。
- 普通用户无法看到未授权资源组中的服务。
- 多探活项结果能按嵌套在线规则正确计算服务状态。
- 旧服务、探活配置和用户授权能幂等迁移且原数据不删除。
- 后端测试通过，前端类型检查和构建通过。

## 非目标

- 不提供 Docker、Kubernetes、LDAP、SSO、分布式调度或高可用；Agent 扩展由 `2026-08-04-agent-design.md` 定义。
- 不保存任意 SSH 私钥内容，仅支持密码或服务器本地私钥路径。
