# 服务详情、监控生命周期与直接启动设计规格

## 状态

- 产品方向：用户已确认。
- 书面规格：用户已批准，实现已完成并进入验证。
- 架构评审：必须；本轮涉及 API、日志保留、调度、身份凭据、TLS 和发布包边界。
- ADR 信号：是；实现完成后需记录实例 CA 所有权与监控生命周期不变量。

## 目标

- 点击服务卡进入独立详情页，集中展示当前状态、探活项、手动探活结果和 30 天历史。
- 新服务默认不参与定时探活，由管理员显式启用或停止监控。
- 手动探活立即显示本次结果；发现离线时才询问是否执行已配置的启动命令。
- 普通用户可安全修改自己的密码。
- Server 实例默认具备 Agent TLS 证书生成和公共 CA 分发流程。
- 发布包提供根目录 `start.sh`，无需 systemd 和 `install.sh` 即可在当前目录启动。
- 参考 `Wei-Shaw/sub2api` 的信息架构二次优化管理界面，但保留本项目的 React/CSS 组件和视觉令牌。

## 核心不变量

- `Service.enabled` 只表示是否参与定时调度，不限制手动探活、详情查看或历史查询。
- `ProbeLog` 是 SSH 定时探活、SSH 手动探活、Agent 定时上报和 Agent 手动命令的唯一历史源。
- 历史保留以 Server UTC 时间为准，`checked_at < now - 30 days` 的记录必须物理删除。
- 手动拉起服务必须由管理员在查看到本次离线结果后显式确认；不在手动探活路径中自动执行。
- 监控启停和服务进程启动是两个独立动作，前端文案和 API 不得混用。
- 用户自助改密必须校验旧密码；不得复用管理员修改用户的授权路径。
- 发布包不内置通用 CA 私钥。每个 Server 实例首次启动生成自己的 CA 和服务端证书，Agent 只导入公共 CA。

## 方案选择

采用独立服务详情路由、Server 统一日志保留所有者和当前目录发布运行方案。

不采用以下方案：

- 弹窗或侧抽屉服务详情：无独立 URL，刷新后丢失上下文，不适合历史浏览。
- 前端只过滤 30 天历史：无法控制 SQLite 持续增长，也无法保证 API 边界。
- 定时探活离线即弹窗：后台任务没有前台交互上下文，且会把自动监控和人工决策混在一起。
- 根目录 `start.sh` 再启动一套源码开发服务：会和发布二进制行为分叉。

## 服务路由与详情页

- 服务列表使用 `#/services`，服务详情使用 `#/services/{service_id}`。
- 哈希路由解析器识别顶级栏目和可选整数 ID；无效 ID、不存在或无权服务显示明确空状态及返回入口。
- 服务卡整体可点击进入详情；卡片内的编辑、删除和直接操作必须阻止事件冒泡。
- 详情页顶部展示服务名、所属节点、资源组、当前状态、最后检查时间和响应耗时。
- 操作区展示“探活”和“启用监控 / 停止监控”；管理员另可编辑和删除。
- 探活项区展示名称、类型、最近成功状态、最后错误和响应时间，不展示任何认证密钥。
- 历史区按新到旧展示结果、时间、耗时和消息，每页 50 条，通过后端分页加载。

## 手动探活与拉起流程

1. 用户点击“探活”，按钮进入执行中状态。
2. SSH 模式返回即时结果；Agent 模式创建命令并轮询到成功、失败或超时终态。
3. 详情页使用统一结果面板展示本次状态、消息、响应时间和探活项结果，不以页面顶部短暂通知代替。
4. 结果离线、当前用户是管理员且服务已配置启动命令时，弹窗询问是否“拉起服务”。
5. 用户确认后调用启动命令路径，执行完立即复检，并用新结果更新面板与历史。
6. 取消、无启动命令或普通用户不执行拉起，保留原离线结果。

`POST /api/services/{id}/probe` 不得再因管理员身份自动执行启动命令。`POST /api/services/{id}/restart` 仅用于已确认的“拉起并复检”动作。

## 监控启停状态机

- 新建服务时后端 schema、数据库模型和前端表单默认值统一为 `enabled=false`。
- 已有服务的 `enabled` 值保持不变，迁移不会批量停止现有监控。
- “启用监控”将 `enabled` 设为 `true`，并将 `next_check_at` 设为当前时间，使下一轮调度可执行。
- “停止监控”将 `enabled` 设为 `false`，不删除状态和历史，不取消已经开始的单次探活。
- 按钮只在 API 成功后切换文案；失败时保留原状态并显示明确错误。

## 30 天历史保留

- `GET /api/services/{id}/logs` 只查询 `checked_at >= now - 30 days` 的记录，保持服务可见权限校验。
- 接口支持 `limit` 和基于 `(checked_at, id)` 的稳定游标，默认 50 条、最大 100 条，不使用大 offset 扫描。
- 日志保留规则由单一后端函数所有，API 过滤与物理删除共用同一截止时间计算。
- Server 启动时执行一次清理，调度器每日执行一次；清理失败写明确错误日志，不伪装成功。
- 物理删除仅针对 `probe_logs`，不删除服务当前状态、Agent 配置或命令回执。

## 用户自助改密

- 新增已登录用户接口 `PUT /api/auth/password`，请求包含当前密码、新密码和确认密码。
- 后端校验当前密码和新密码强度，密码不正确返回明确 400/422 错误，不泄露哈希细节。
- 修改成功后撤销当前会话并返回登录页，用户使用新密码重新登录。
- 前端在个人账号区提供改密表单，普通用户无需访问管理员的“用户管理”页。

## Agent TLS 证书

- Server 首次初始化时使用 `cryptography` 生成实例独有 CA 和服务端证书，不依赖系统 `openssl`。
- CA 私钥、服务端私钥和运行环境文件权限为 `0600`，公共 CA 证书可下载。
- 证书使用固定 TLS 身份，Agent 配置增加 `tls_server_name`，从而允许 Agent 通过内网 IP 连接且仍严格验证 SAN。
- Agent 接入页提供管理员专用的公共 CA 下载入口；Agent 安装或当前目录运行配置显式引用该 CA。
- 缺失证书、证书无效或身份不匹配时 Agent gRPC 明确启动失败，不降级为明文或跳过验证。

## 根目录 `start.sh`

- Server 发布包根目录包含可执行 `start.sh`，与 Server 二进制、校验文件、`install.sh` 和平台检测脚本一同发布。
- 脚本根据 `uname -m` 和 `getconf GNU_LIBC_VERSION` 在当前目录选择最高兼容的 Server 二进制；未找到兼容产物时明确退出。
- 首次运行创建 `./data`、`./certs` 和权限 `0600` 的 `./.service-monitor.env`。
- 首次运行生成高熵 `APP_SECRET`、随机管理员密码、实例 CA 和 Server 证书；SQLite 和证书始终保存在当前目录。
- 首次成功初始化后向终端打印访问地址、管理员用户名和随机密码。重复运行复用现有配置，不重置密码，也不再打印旧密码。
- 脚本以前台方式 `exec` Server 二进制，`Ctrl+C` 直接停止；可通过 `PORT` 覆盖默认端口。
- 现有 `scripts/start.sh` 仍仅作为源码开发入口，发布包根目录 `start.sh` 是独立的二进制运行入口。
- `install.sh` 继续负责 root/systemd 安装；`start.sh` 不写入 `/etc`、`/usr/local/bin` 或 systemd。

## 界面优化范围

- 保留可折叠侧边栏，增大选中区域和文字容器，确保小屏幕不截断。
- 页面顶部使用紧凑的标题、说明和主操作，首页提供可扫描的状态统计与服务列表。
- 表格和历史区使用统一工具栏、空状态、加载状态和错误状态，不将主要结果只放在 Toast 中。
- 参考 `sub2api` 的布局层级、监控时间线和密码区域；不复制 Vue/Tailwind 实现，不引入渐变、玻璃效果或过度卡片化。
- 继续使用 Lucide 图标、现有 UI 原语和项目颜色/字号/间距令牌，删除本轮替代后无引用的前端组件、样式和旧状态路径。

## API 与兼容边界

- 保留现有服务 CRUD、`/probe`、`/restart` 和 Agent 命令查询路径，只收紧其行为语义。
- 扩展 `ProbeResultOutput` 以返回各探活项结果；SSH 即时执行和 Agent 命令终态转换为同一前端结果模型。
- 日志接口调整为带分页元数据的响应，前端不再假设返回固定数组。
- 普通用户继续只能读取已授权资源组服务和执行手动探活；启停监控、编辑、删除、拉起服务和下载 Agent CA 仅限管理员。
- 数据迁移不删除现有服务和 30 天内日志；首次新版启动时删除已超出保留期的日志。

## 验收标准

- 点击任一可见服务卡进入其独立详情 URL，刷新后仍显示同一服务。
- 详情页能展示最近 30 天历史并分页加载，API 不返回 30 天前记录，定时清理后 SQLite 中不再存在这些记录。
- SSH 和 Agent 手动探活都显示本次终态结果；离线时仅管理员看到拉起确认弹窗。
- 新服务保存后为“监控已停止”，点击启用后参与调度，按钮变为“停止监控”。
- 已启用旧服务升级后仍启用，不发生批量状态变更。
- 用户输入正确旧密码后可修改密码，修改成功后需使用新密码重新登录；错误旧密码不改变任何数据。
- 全新 Server 目录执行 `./start.sh` 后自动生成配置、随机密码和 TLS 文件，并以前台进程提供前后端；第二次执行不重置密码。
- Agent 使用下载的公共 CA 和配置的 TLS 身份能严格连接 Server，错误 CA 或身份连接失败。
- 目标后端测试、前端类型检查、前端构建、发布布局测试和 Shell 静态检查通过。

## 非目标

- 不增加无限期历史、历史导出或外部时序数据库。
- 不为普通用户开放监控启停或启动命令。
- 不为 `start.sh` 实现后台守护、开机自启、日志轮转或自动更新；这些继续由 `install.sh`/systemd 负责。
- 不提供关闭 TLS 验证、共享内置 CA 私钥或明文 Agent 通信。
- 不替换 React、Vite、现有 CSS 令牌或 Lucide 图标集。

## 实现影响

### 产品与架构基线

- 产品需求基线：本次对话确认的六项问题、手动离线后弹窗拉起、当前目录 `start.sh`、独立服务详情页和 30 天物理保留。
- 架构基线：`2026-08-03-service-monitor-design.md`、`2026-08-04-agent-design.md` 和 `2026-08-04-agent-execution-and-identity.md`。
- 对齐结果：现有实现对已确认需求存在实现偏离，本规格收紧行为而不更换核心架构。

### 影响所有者

- 后端：服务 API/schema、监测结果、日志保留、调度器、认证、Agent TLS、配置与启动。
- 前端：哈希路由、服务列表/详情、Agent 接入、个人账号、布局与不再使用代码清理。
- 发布：Server 发布目录、根目录 `start.sh`、平台选择、GitHub Actions 打包和安装文档。

### 复杂度预算

- 现有 `ServicesPage.tsx` 已同时承担列表、表单和所有操作，新详情应拆为独立页面和服务领域组件。
- 日志保留应新增单一后端 owner 函数，调度器和启动钩子只调用它，不复制截止规则。
- TLS 文件生成应与 Agent gRPC Server 启动分层，便于 `start.sh`、`install.sh` 和测试共用。

## 验证方法

- 后端定向测试：服务默认状态、启停、手动探活不自动拉起、日志分页与 30 天物理清理、改密、CA 生成和下载。
- Agent/gRPC 定向测试：严格 CA 校验、TLS 身份、命令终态结果和历史写入。
- 前端静态验证：TypeScript 类型检查和 Vite 生产构建；按用户要求不使用 `dev-browser`。
- 发布验证：布局测试、`shellcheck`、二进制 `--self-test`、首次/再次 `start.sh` 行为以及 GitHub Actions 产物列表。
