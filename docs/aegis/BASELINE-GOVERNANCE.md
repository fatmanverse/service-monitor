# 基线治理

## 基线的含义

用户确认的功能范围是**产品基线**。`specs/` 下的设计规格是**架构与验收基线**。二者共同构成实现的约束——代码、测试、文档必须同步维护，不以隐式兼容分支替代明确契约。

## 不变量的强制性

规格中「核心不变量」一节列出的约束不是建议，违反即为架构缺陷。不接受以配置开关、兼容分支或「临时方案」绕过。

若确实需要突破某条不变量，流程是：先修订规格并说明代价与影响范围，经用户确认后再实施。不允许先改代码再补文档。

## 高风险模块的额外要求

以下模块的变更需要专门的安全评审，评审记录留存于 `work/`：

**会话代理（堡垒机）**。评审范围至少覆盖：授权绕过路径、命令注入、录像完整性、会话隔离、凭据泄露。理由见 [自研会话代理 ADR](adr/2026-08-07-bastion-self-build.md)——此模块被攻破等同于全部纳管主机失陷。

**权限判定**。任何对鉴权逻辑的修改需构造越权测试用例，覆盖新增与修改的权限码。

**凭据管理**。加密、解密、轮换路径的变更需确认凭据不出现在日志、审计记录与 API 响应中。

**Agent 命令执行**。需确认参数化执行未退化为字符串拼接。

## 测试要求

核心模块（权限、任务、健康规则、凭据）单元测试覆盖率不低于 80%。

以下场景必须有自动化测试，不接受人工验证：

- 任务的恰好一次语义（并发领取、租约回收、幂等键）
- 越权访问被拒绝
- 写操作产生审计记录
- 数据库迁移可重复执行且可回滚

## 文档同步

功能合并前，对应的规格、ADR、实施计划必须已更新。发现文档与实现不一致时，视为缺陷处理。
